# 会议室预定系统 - 代码分析报告

## 一、项目概述

本项目是一个基于 Vue 3 + TypeScript + Pinia 的会议室预定管理系统，提供了完整的会议室预定、审批、管理功能，并支持周期性预定和候补排队机制。

---

## 二、主要模块概览

系统包含以下 **5个主要模块**：

| 序号 | 模块名称 | 组件文件 | 功能描述 | 权限要求 |
|------|----------|----------|----------|----------|
| 1 | 用户认证模块 | AppHeader.vue | 用户切换、角色识别 | 所有用户 |
| 2 | 会议室预定模块 | CalendarView.vue | 查看时间表、创建预定、加入候补 | 所有用户 |
| 3 | 会议室管理模块 | RoomManagement.vue | 会议室的增删改查、启用/禁用 | 仅管理员 |
| 4 | 审批管理模块 | ApprovalManagement.vue | 审批/驳回预定申请 | 仅管理员 |
| 5 | 我的预定模块 | MyReservations.vue | 查看个人预定记录和候补状态 | 所有用户 |

---

## 三、模块执行顺序

系统的使用流程遵循以下顺序：

```
┌─────────────────────────────────────────────────────────────────┐
│                        系统启动                                  │
│                           ↓                                      │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │  第一步：用户认证模块 (AppHeader.vue)                     │    │
│  │  - 选择当前用户身份                                       │    │
│  │  - 系统识别用户角色（管理员/普通用户）                     │    │
│  └─────────────────────────────────────────────────────────┘    │
│                           ↓                                      │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │  第二步：根据角色显示可用模块                              │    │
│  │  - 普通用户：预定、我的预定                               │    │
│  │  - 管理员：预定、管理、审批、我的预定                      │    │
│  └─────────────────────────────────────────────────────────┘    │
│                           ↓                                      │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │  第三步：核心业务操作                                      │    │
│  │  - 管理员：先配置会议室 → 用户提交预定 → 管理员审批        │    │
│  │  - 普通用户：选择会议室 → 提交预定 → 等待审批              │    │
│  └─────────────────────────────────────────────────────────┘    │
│                           ↓                                      │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │  第四步：查看结果                                          │    │
│  │  - 在"我的预定"中查看预定状态和候补状态                    │    │
│  └─────────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────────┘
```

### 详细执行顺序说明

1. **初始化阶段**：系统加载，读取预设用户列表和会议室列表
2. **用户选择阶段**：用户通过下拉菜单选择身份（管理员或普通用户）
3. **模块导航阶段**：根据用户角色显示对应的Tab标签页
4. **业务操作阶段**：
   - 管理员路径：会议室管理 → 审批管理 → 我的预定
   - 普通用户路径：会议室预定 → 我的预定
5. **结果查看阶段**：在"我的预定"模块查看所有预定和候补的状态

## 五、预定排队与候补功能详解

### 5.1 功能概述

候补功能允许用户在目标时段已被占用时，加入排队队列。当原预定被取消时，系统自动按顺序将时段分配给候补用户。

### 5.2 核心数据结构

**候补记录 (WaitlistEntry)**：
```typescript
interface WaitlistEntry {
  id: string,                    // 候补记录ID
  roomId: string,                // 会议室ID
  userId: string,                // 用户ID
  date: string,                  // 日期
  startTime: string,             // 开始时间
  endTime: string,               // 结束时间
  title: string,                 // 会议主题
  createdAt: string,             // 创建时间
  position: number,              // 排队位置
  status: 'waiting' | 'assigned' | 'cancelled',  // 状态
  assignedReservationId?: string // 分配后的预定ID
}
```

### 5.3 候补状态流转

```
┌─────────────┐
│   waiting   │ ← 初始状态：排队等待中
│  (排队中)   │
└──────┬──────┘
       │
       ├──→ 用户主动取消 ──→ ┌─────────────┐
       │                     │  cancelled  │
       │                     │  (已取消)   │
       │                     └─────────────┘
       │
       └──→ 有预定取消，自动分配 ──→ ┌─────────────┐
                                     │  assigned   │
                                     │  (已分配)   │
                                     └─────────────┘
```

### 5.4 候补流程详解

**流程1：加入候补队列**

| 步骤 | 操作 | 系统处理 |
|------|------|----------|
| 1 | 用户点击已被占用的时间槽 | 显示预定详情弹窗 |
| 2 | 点击"加入候补"按钮 | 打开候补表单 |
| 3 | 输入会议主题 | 必填字段 |
| 4 | 显示当前排队人数 | 计算该时段已有候补数量 |
| 5 | 点击"确认候补" | 调用 `addToWaitlist()` |

**系统处理逻辑**：
```typescript
function addToWaitlist(roomId, date, startTime, endTime, title) {
  // 1. 查询该时段已有的候补记录
  const existingEntries = waitlist.filter(
    w => w.roomId === roomId && w.date === date && w.status === 'waiting'
  )
  
  // 2. 计算排队位置
  const position = existingEntries.length + 1
  
  // 3. 创建候补记录
  const entry = {
    id: generateId(),
    roomId, userId, date, startTime, endTime, title,
    createdAt: new Date().toISOString(),
    position,
    status: 'waiting'
  }
  
  // 4. 添加到候补列表
  waitlist.push(entry)
  
  return entry
}
```

**流程2：自动分配候补**

触发条件：当预定被取消时

| 步骤 | 触发事件 | 系统处理 |
|------|----------|----------|
| 1 | 预定被取消 | 调用 `processWaitlistForSlot()` |
| 2 | 查询候补队列 | 获取该时段所有 waiting 状态的候补，按 position 排序 |
| 3 | 检查时间冲突 | 对每个候补检查是否仍有冲突 |
| 4 | 自动创建预定 | 为无冲突的候补创建 approved 状态的预定 |
| 5 | 更新候补状态 | 将候补状态改为 'assigned'，记录预定ID |
| 6 | 重排序队列 | 重新计算剩余候补的排队位置 |

**自动分配处理逻辑**：
```typescript
function processWaitlistForSlot(roomId, date, startTime, endTime) {
  // 1. 获取该时段所有等待中的候补，按位置排序
  const allWaitingEntries = waitlist.filter(
    w => w.roomId === roomId && w.date === date && w.status === 'waiting'
  ).sort((a, b) => a.position - b.position)
  
  // 2. 遍历候补，尝试分配
  for (const entry of allWaitingEntries) {
    // 检查是否仍有时间冲突
    if (!checkTimeConflict(roomId, date, entry.startTime, entry.endTime)) {
      // 创建自动审批的预定
      const newReservation = {
        id: generateId(),
        roomId, date,
        startTime: entry.startTime,
        endTime: entry.endTime,
        title: entry.title,
        userId: entry.userId,
        status: 'approved',
        createdAt: new Date().toISOString(),
        approvedAt: new Date().toISOString(),
        approvedBy: 'system'  // 系统自动审批
      }
      
      reservations.push(newReservation)
      
      // 更新候补状态
      entry.status = 'assigned'
      entry.assignedReservationId = newReservation.id
    }
  }
  
  // 3. 重新排序剩余候补
  reorderWaitlist(roomId, date)
}
```

**流程3：取消候补**

| 步骤 | 操作 | 系统处理 |
|------|------|----------|
| 1 | 用户在"我的预定"点击"取消候补" | 弹出确认对话框 |
| 2 | 确认取消 | 调用 `cancelWaitlistEntry(id)` |
| 3 | 系统更新 | 状态改为 'cancelled' |
| 4 | 重排序 | 调用 `reorderWaitlist()` 更新其他人的排队位置 |

**重排序逻辑**：
```typescript
function reorderWaitlist(roomId, date) {
  // 获取该会议室该日期所有等待中的候补
  const entries = waitlist.filter(
    w => w.roomId === roomId && w.date === date && w.status === 'waiting'
  ).sort((a, b) => a.position - b.position)
  
  // 重新分配位置编号
  entries.forEach((entry, index) => {
    entry.position = index + 1
  })
}
```

### 5.5 候补功能的触发场景

| 场景 | 触发函数 | 说明 |
|------|----------|------|
| 普通预定取消 | `cancelReservation()` → `processWaitlistForSlot()` | 触发候补分配 |
| 单次周期预定取消 | `cancelSingleRecurrence()` → `processWaitlistForSlot()` | 触发该日期的候补分配 |
| 整个周期预定取消 | `cancelAllRecurrences()` → 每个预定都触发 `processWaitlistForSlot()` | 每个日期分别触发 |

### 5.6 候补功能的关键规则

1. **排队规则**：先到先得，按加入时间排序
2. **自动审批**：候补转预定后自动获得 approved 状态，审批人为 'system'
3. **冲突检查**：分配前检查是否仍有时间冲突，避免重复分配
4. **位置更新**：有人取消候补后，自动更新其他人的排队位置
5. **状态追踪**：候补记录保留 assigned 状态，可追溯分配结果
