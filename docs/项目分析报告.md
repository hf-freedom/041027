# 会议室预定系统 - 项目分析报告

## 一、项目概述

这是一个基于 Vue 3 + TypeScript + Pinia 的会议室预定管理系统，支持用户预定会议室、管理员审批、预定排队与候补、周期性预定等功能。

---

## 二、主要模块

系统分为 **5 个核心模块**，按用户使用流程顺序排列：

| 序号 | 模块名称 | 访问权限 | 主要功能 |
|------|----------|----------|----------|
| 1 | **用户切换模块** | 所有用户 | 切换当前登录用户（管理员/普通用户） |
| 2 | **会议室预定模块** | 所有用户 | 查看会议室、选择时间段、提交预定、加入候补 |
| 3 | **我的预定模块** | 所有用户 | 查看个人预定记录、取消预定、管理候补队列 |
| 4 | **审批管理模块** | 仅管理员 | 审批预定申请（通过/驳回） |
| 5 | **会议室管理模块** | 仅管理员 | 会议室的增删改查、启用/禁用 |

---

## 三、模块执行顺序

### 整体流程顺序

```
用户切换模块
    ↓
会议室预定模块 (核心入口)
    ↓
        ├─ 普通用户 → 提交预定 → 等待审批 → 审批管理模块（管理员操作）
        │                           ↓
        │                     通过/驳回
        │                           ↓
        └──────────────────── 我的预定模块（查看状态/取消）
    ↓
预定排队与候补功能（贯穿预定和我的预定模块）
```

### 详细先后顺序

1. **第一步**：用户进入系统，首先在 `AppHeader` 中切换用户身份（管理员/普通用户）
2. **第二步**：默认进入「会议室预定」页面，查看会议室时间网格
3. **第三步**：点击可预定时间段 → 填写预定信息 → 提交预定
   - 管理员：直接通过，无需审批
   - 普通用户：进入待审批状态
4. **第四步**：管理员进入「审批管理」页面，审批待处理申请
5. **第五步**：所有用户进入「我的预定」页面，查看预定状态、取消预定、管理候补
6. **第六步**（管理员）：进入「会议室管理」，维护会议室基础信息

### 3. 预定排队与候补功能（重点）

#### 3.1 功能定位

**贯穿整个预定流程的核心机制**，解决时间段冲突问题，实现自动化资源分配。

#### 3.2 加入候补流程（两种入口）

##### 入口一：预定时间冲突时自动触发

| 步骤 | 操作 | 字段/按钮 | 返回结果 |
|------|------|-----------|----------|
| 1 | 用户提交预定 | 正常填写预定表单，点击确认 | 系统检测时间冲突 |
| 2 | 冲突确认弹窗 | 系统提示：「该时间段已被预定，是否加入候补队列？」 | - 点击「确定」→ 进入候补弹窗<br>- 点击「取消」→ 返回预定表单 |
| 3 | 填写候补会议主题 | `title` 输入框 | 必填验证 |
| 4 | 查看候补信息 | 会议室、日期、时间、当前排队人数 | 显示排在你前面有多少人 |
| 5 | 点击「确认候补」 | 橙色按钮 | 提示：「已加入候补队列，当有人取消预定后将自动分配给您。」 |

##### 入口二：预定详情页手动加入

| 步骤 | 操作 | 字段/按钮 | 返回结果 |
|------|------|-----------|----------|
| 1 | 点击已被预定的时间槽 | 时间网格中红色/橙色格子 | 打开预定详情弹窗 |
| 2 | 点击「加入候补」按钮 | 详情页中部橙色按钮 | 打开候补弹窗，同入口一步骤3 |

#### 3.3 候补队列数据结构 (WaitlistEntry)

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `id` | string | 候补记录唯一ID |
| `roomId` | string | 会议室ID |
| `userId` | string | 用户ID |
| `date` | string | 日期 YYYY-MM-DD |
| `startTime` | string | 开始时间 HH:mm |
| `endTime` | string | 结束时间 HH:mm |
| `title` | string | 会议主题 |
| `createdAt` | string | 加入候补时间 |
| `position` | number | 排队位置，从1开始 |
| `status` | string | waiting/assigned/cancelled |
| `assignedReservationId` | string | 分配成功后的预定ID |

#### 3.4 候补自动分配机制（核心算法）

**触发时机**：当有人取消预定（包括单次取消、周期取消）时自动触发

```
执行流程：
1. 获取该会议室 + 该日期下所有 status = 'waiting' 的候补记录
2. 按 position 从小到大排序（先来先服务）
3. 遍历每条候补记录：
   a. 检查该候补的时间段是否还有冲突
   b. 如果没有冲突：
      i. 自动创建一条新的预定记录，status = 'approved'
      ii. 审批人标记为 'system'
      iii. 将该候补状态改为 'assigned'，记录分配的预定ID
   c. 如果仍有冲突，跳过该用户，继续下一位
4. 重新排序该会议室该日期下所有候补的 position
```

**代码位置**：`stores/index.ts:366-397` `processWaitlistForSlot` 函数

#### 3.5 取消候补流程

| 步骤 | 操作 | 字段/按钮 | 返回结果 |
|------|------|-----------|----------|
| 1 | 进入「我的预定」→「候补队列」 | 候补列表卡片 | 显示当前排队位置 |
| 2 | 点击「取消候补」按钮 | 红色小按钮 | 确认弹窗 |
| 3 | 确认取消 | 系统二次确认 | - 该候补 status 改为 cancelled<br>- 该会议室该日期下所有候补重新排序，position 自动减1补位 |

## 五、周期性预定功能说明

### 支持的周期类型

1. **每日**：按天数间隔重复
2. **每周**：可选择周一至周日中的多天重复
3. **每月**：按月间隔重复
4. **自定义间隔**：自定义天数间隔

### 重要特性

- 周期预定创建后生成一个 `RecurrenceSeries` 系列记录
- 系列中每个日期生成独立的 `Reservation` 记录
- 审批/驳回主预定会自动应用到整个系列
- 支持「取消全部」和「取消本次」两种操作
- 取消后自动触发对应日期的候补分配

---

## 六、核心数据模型关系

```
User (用户)
    ↓ 1:N
Reservation (预定) ← 1:1 → WaitlistEntry (候补分配成功)
    ↓ N:1            ↓ N:1
MeetingRoom (会议室)
    ↓ 1:N            ↓ 1:1
RecurrenceSeries (周期系列) ← 1:N ← Reservation (周期子预定)
```

## 七、状态枚举说明

### ReservationStatus 预定状态

| 状态值 | 显示文本 | 说明 |
|--------|----------|------|
| `pending` | 待审批 | 普通用户提交后默认状态 |
| `approved` | 已通过 | 管理员审批通过 / 管理员直接预定 |
| `rejected` | 已驳回 | 管理员驳回 |
| `cancelled` | 已取消 | 用户取消 |
| `waitlist` | 候补中 | （预留状态，实际使用WaitlistEntry） |

### WaitlistEntry 候补状态

| 状态值 | 显示文本 | 说明 |
|--------|----------|------|
| `waiting` | 排队中 | 正在等待分配 |
| `assigned` | 已分配 | 系统已自动分配预定 |
| `cancelled` | 已取消 | 用户主动取消 |
