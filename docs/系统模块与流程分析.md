# 会议室预定系统 - 模块与流程分析文档

## 一、系统概述

本项目是一个基于 Vue 3 + TypeScript + Pinia 的会议室预定系统，支持会议室管理、预定申请、审批流程、周期性预定以及候补排队功能。

---

## 二、系统模块概览

系统共包含 **5 个主要模块**，按功能依赖关系排序如下：

| 序号 | 模块名称 | 对应文件 | 功能说明 | 依赖模块 |
|------|----------|----------|----------|----------|
| 1 | 用户与权限模块 | AppHeader.vue + stores/index.ts | 用户切换、角色管理 | 无（基础模块） |
| 2 | 会议室管理模块 | RoomManagement.vue | 会议室的增删改查 | 用户与权限模块 |
| 3 | 会议室预定模块 | CalendarView.vue | 预定申请、周期性预定 | 会议室管理模块 |
| 4 | 审批管理模块 | ApprovalManagement.vue | 预定审批（通过/驳回） | 会议室预定模块 |
| 5 | 我的预定模块 | MyReservations.vue | 查看/取消预定、候补管理 | 会议室预定模块、审批管理模块 |

### 2.2 模块执行先后顺序

#### 系统启动顺序
```
步骤1: 初始化用户与权限模块
        ↓ 加载用户列表，设置默认当前用户
步骤2: 初始化会议室管理模块
        ↓ 加载会议室列表
步骤3: 初始化会议室预定模块
        ↓ 加载预定数据、候补数据
步骤4: 初始化审批管理模块
        ↓ 计算待审批数量
步骤5: 初始化我的预定模块
        ↓ 筛选当前用户的预定和候补记录
```

#### 业务流程执行顺序

**场景A：普通用户完整预定流程**
```
用户与权限模块（登录）
        ↓
会议室管理模块（查看可用会议室）
        ↓
会议室预定模块（提交预定申请）
        ↓
审批管理模块（管理员审批）
        ↓
我的预定模块（查看审批结果）
```

**场景B：管理员直接预定流程**
```
用户与权限模块（切换为管理员）
        ↓
会议室管理模块（查看会议室）
        ↓
会议室预定模块（提交预定，自动通过）
        ↓
我的预定模块（直接查看已通过的预定）
```

**场景C：候补分配流程**
```
我的预定模块（用户A取消预定）
        ↓
会议室预定模块（触发候补处理流程）
        ↓
我的预定模块（用户B收到自动分配的预定）
```

## 三、各模块详细流程

### 模块1：用户与权限模块

#### 3.1.1 模块职责
- 管理当前登录用户
- 提供用户切换功能
- 区分管理员和普通用户权限

#### 3.1.2 数据结构
```typescript
interface User {
  id: string
  name: string
  role: 'admin' | 'user'
}
```

#### 3.1.3 流程详情

**流程1：用户切换**

| 步骤 | 操作 | 触发条件 | 返回结果 |
|------|------|----------|----------|
| 1 | 点击右上角用户选择器 | 用户点击下拉按钮 | 展开用户列表下拉菜单 |
| 2 | 选择目标用户 | 用户点击列表中的某用户 | 切换当前用户，页面刷新 |

**关键代码逻辑：**
- 初始用户：`initialUsers[1]`（张三，普通用户）
- 管理员用户：`initialUsers[0]`（管理员）
- 切换方法：`store.setCurrentUser(userId)`

**权限影响：**
- 管理员(`role === 'admin'`)：
  - 预定自动通过，无需审批
  - 可访问"会议室管理"和"审批管理"标签页
- 普通用户(`role === 'user'`)：
  - 预定需等待管理员审批
  - 只能访问"会议室预定"和"我的预定"标签页

### 模块2：会议室管理模块

#### 3.2.1 模块职责
- 会议室信息的增删改查
- 会议室启用/禁用状态管理
- 设置会议室开放时间

#### 3.2.2 数据结构
```typescript
interface MeetingRoom {
  id: string
  name: string
  location: string
  disabled: boolean
  openTimeStart: string  // 如 "08:00"
  openTimeEnd: string    // 如 "18:00"
}
```

#### 3.2.3 流程详情

**流程1：添加会议室**

| 步骤 | 操作 | 输入字段 | 校验规则 | 返回结果 |
|------|------|----------|----------|----------|
| 1 | 点击"添加会议室"按钮 | 无 | 无 | 打开添加弹窗 |
| 2 | 填写会议室信息 | name, location, openTimeStart, openTimeEnd | 名称和位置不能为空 | 表单数据 |
| 3 | 设置启用状态 | enabled（开关） | 无 | true/false |
| 4 | 点击"保存" | 无 | 校验必填字段 | 新增会议室到列表 |

**表单字段说明：**
- `name`：会议室名称（必填）
- `location`：会议室位置（必填）
- `openTimeStart`：开放开始时间，默认"08:00"
- `openTimeEnd`：开放结束时间，默认"18:00"
- `enabled`：是否启用（开关，默认启用）

**流程2：编辑会议室**

| 步骤 | 操作 | 触发条件 | 返回结果 |
|------|------|----------|----------|
| 1 | 点击"编辑"按钮 | 用户点击某会议室的编辑按钮 | 打开编辑弹窗，回填数据 |
| 2 | 修改信息 | 用户修改表单字段 | 更新后的表单数据 |
| 3 | 点击"保存" | 用户确认保存 | 更新会议室信息 |

**流程3：启用/禁用会议室**

| 步骤 | 操作 | 触发条件 | 返回结果 |
|------|------|----------|----------|
| 1 | 点击状态切换按钮 | 用户点击"启用"或"禁用"按钮 | 会议室状态切换 |

**流程4：删除会议室**

| 步骤 | 操作 | 触发条件 | 返回结果 |
|------|------|----------|----------|
| 1 | 点击"删除"按钮 | 用户点击删除按钮 | 弹出确认对话框 |
| 2 | 确认删除 | 用户点击"删除"确认 | 从列表中移除会议室 |

### 模块3：会议室预定模块（核心模块）

#### 3.3.1 模块职责
- 查看会议室时间段占用情况
- 提交预定申请（单次/周期性）
- 处理时间冲突检测
- 候补排队功能入口

#### 3.3.2 数据结构
```typescript
interface Reservation {
  id: string
  roomId: string
  userId: string
  date: string
  startTime: string
  endTime: string
  title: string
  status: 'pending' | 'approved' | 'rejected' | 'cancelled' | 'waitlist'
  createdAt: string
  approvedAt?: string
  approvedBy?: string
  rejectReason?: string
  recurrenceId?: string
  recurrenceRule?: RecurrenceRule
  isRecurrenceMaster?: boolean
  originalOccurrenceDate?: string
}

interface RecurrenceRule {
  type: 'none' | 'daily' | 'weekly' | 'monthly' | 'custom'
  interval: number
  daysOfWeek?: number[]
  dayOfMonth?: number
  endDate?: string
  maxOccurrences?: number
}
```

#### 3.3.3 流程详情

**流程1：查看会议室时间表**

| 步骤 | 操作 | 输入/触发 | 返回结果 |
|------|------|----------|----------|
| 1 | 选择会议室 | 从下拉框选择 | 显示该会议室的时间网格 |
| 2 | 选择日期 | 从日期选择器选择 | 显示该日期的时间段状态 |
| 3 | 查看时间段 | 系统自动加载 | 30分钟为单位的时间段列表 |

**时间段状态说明：**
- **可预定**（白色）：该时段无人预定
- **已被预定**（红色）：已被其他用户预定且已批准
- **审批中**（橙色）：已被预定但待审批
- **我的预定**（绿色）：当前用户的预定
- **有候补**（黄色边框）：该时段有可候补队列
- **非开放时间**（灰色）：会议室未开放时段

**流程2：提交单次预定**

| 步骤 | 操作 | 输入字段 | 校验规则 | 返回结果 |
|------|------|----------|----------|----------|
| 1 | 点击空闲时段 | 用户点击可预定时段 | 无 | 打开预定弹窗 |
| 2 | 填写会议主题 | title | 不能为空 | 表单数据 |
| 3 | 选择开始时间 | startTime | 必须在开放时间内 | 时间选项列表 |
| 4 | 选择结束时间 | endTime | 必须晚于开始时间 | 时间选项列表 |
| 5 | 检测时间冲突 | 系统自动检测 | 检查是否与其他预定冲突 | 冲突/无冲突 |
| 6a | 无冲突：确认预定 | 点击"确认预定" | 校验通过 | 创建预定记录 |
| 6b | 有冲突：加入候补 | 点击"加入候补" | 无 | 跳转到候补流程 |

**预定状态规则：**
- 管理员预定：`status = 'approved'`，自动通过
- 普通用户预定：`status = 'pending'`，需等待审批

**流程3：提交周期性预定**

| 步骤 | 操作 | 输入字段 | 选项说明 | 返回结果 |
|------|------|----------|----------|----------|
| 1 | 勾选"周期性预定" | isRecurring | 复选框 | 展开周期设置 |
| 2 | 选择重复类型 | recurrenceType | daily/weekly/monthly/custom | 不同类型不同选项 |
| 3 | 设置间隔/星期 | interval/daysOfWeek | 根据类型变化 | 周期规则参数 |
| 4 | 设置结束条件 | endDate/maxOccurrences | 二选一 | 结束条件 |
| 5 | 预览日期 | 系统自动计算 | 显示前10次日期 | 日期预览列表 |
| 6 | 确认预定 | 点击"确认预定" | 生成所有周期实例 | 批量创建预定 |

**重复类型说明：**
- **每日**：每隔 N 天重复一次
- **每周**：可选择具体星期几（可多选）
- **每月**：每隔 N 个月重复一次
- **自定义**：每隔 N 天重复一次

**流程4：查看预定详情**

| 步骤 | 操作 | 触发条件 | 返回结果 |
|------|------|----------|----------|
| 1 | 点击已预定时段 | 用户点击有预定的时段 | 打开详情弹窗 |
| 2 | 查看详情 | 系统自动显示 | 会议主题、预定人、时间、状态 |
| 3 | 候补操作 | 如非本人预定 | 显示"加入候补"按钮 |

## 四、预定排队与候补功能详解

### 4.1 功能概述

候补功能允许用户在会议室时段已被预定的情况下，加入等待队列。当有人取消预定时，系统会自动按顺序将会议室分配给候补队列中的用户。

### 4.2 数据结构

```typescript
interface WaitlistEntry {
  id: string
  roomId: string
  userId: string
  date: string
  startTime: string
  endTime: string
  title: string
  createdAt: string
  position: number      // 排队位置
  status: 'waiting' | 'assigned' | 'cancelled'
  assignedReservationId?: string  // 分配后的预定ID
}
```

### 4.3 候补流程详解

**流程1：加入候补队列**

```
┌─────────────────────────────────────────────────────────────────┐
│  触发条件：用户尝试预定已被占用的时段                              │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐

**流程2：候补转正式预定（自动分配）**

```
┌─────────────────────────────────────────────────────────────────┐
│  触发条件：用户取消预定或预定被驳回                                │

                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│  步骤1：调用 processWaitlistForSlot()                             │

└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│  步骤2：获取该时段的候补队列                                       │
│  - 筛选条件：roomId, date, status='waiting'                       │
│  - 排序：按 position 升序（先到先服务）                            │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│  步骤3：遍历候补队列尝试分配                                       │
│  FOR each entry in waitlist:                                     │
│    1. 检查该 entry 的时间是否仍冲突                                │

│       - 创建新的 Reservation 记录                                 │
│       - status = 'approved'（系统自动分配）                        │

│       - 更新 entry.status = 'assigned'                            │

│  步骤4：重新排序候补队列                                          │

## 五、模块执行顺序总结

### 5.1 系统初始化流程

```
1. 加载用户数据 → 设置当前用户（默认张三）
2. 加载会议室数据 → 显示可用会议室列表
3. 加载预定数据 → 计算各时段占用状态
4. 加载候补数据 → 计算候补队列
```

### 5.2 典型业务流程

**场景1：普通用户预定会议室**
```
用户切换模块 → 会议室预定模块 → 审批管理模块（等待）→ 我的预定模块
```

**场景2：管理员预定会议室**
```
用户切换模块 → 会议室预定模块 → 我的预定模块（自动通过）
```

**场景3：管理员审批流程**
```
用户切换模块（管理员）→ 审批管理模块 → 我的预定模块（用户查看）
```

**场景4：候补分配流程**
```
我的预定模块（取消）→ 系统自动触发候补处理 → 我的预定模块（被分配者查看）
```

## 八、注意事项

1. **时间冲突检测**：系统以30分钟为最小粒度检测冲突
2. **周期预定限制**：最大生成50次预定实例
3. **候补自动分配**：取消预定后会自动触发候补处理
4. **权限控制**：普通用户无法访问管理功能
5. **数据持久化**：当前使用内存存储，刷新页面数据会重置
